# Residential Prosumer Forecasting and Anomaly Detection Thesis Project

This GitHub-ready folder is a privacy-conscious export of the cleaned Candidate C research project. It keeps the reproducible code path and selected derived outputs while excluding raw Home Assistant exports, local model artifacts, cache folders, and manual-review archives.

## Project Overview

The project studies energy-demand forecasting and residual-based anomaly detection for a monitored villa / residential prosumer setting. The workflow starts from Home Assistant sensor telemetry, builds an hourly master dataset, creates A1-B4 modelling datasets, trains forecasting baselines and machine-learning models, evaluates forecast quality, and applies residual-MAD anomaly detection.

## Workflow

1. **Configuration and reproducibility**: configuration files, helper scripts, and tests live under `src/config/`.
2. **Preprocessing**: scripts under `src/preprocessing/` transform sensor exports into an hourly master dataset.
3. **Dataset design**: `src/dataset_design/` contains the A1-B4 dataset-generation and validation workflow.
4. **Split generation**: `src/splits/` creates chronological/rolling splits and split tables.
5. **Model training and prediction**: training scripts are under `src/model_training/`; lightweight prediction material is under `src/prediction/` and `outputs/predictions/`.
6. **Evaluation**: metric scripts and selected outputs are under `src/evaluation/` and `outputs/metrics/`.
7. **Anomaly detection**: residual-MAD logic and outputs are under `src/anomaly_detection/` and `outputs/anomaly_detection/`.
8. **Reporting**: reporting scripts and final figures/timeline materials are under `src/reporting/` and `outputs/figures/`.

## Dataset Design

The A1-B4 matrix preserves scientifically meaningful dataset variants, including demand-only versus demand-plus-telemetry designs, clean-only versus imputed rows, and related experimental labels. Identically valued files can still represent different experimental conditions when filenames encode different A/B or A1-B4 variants.

## Phase 1 and Phase 2

**Phase 1 holdout** represents the chronological holdout work used to test the modelling approach on a fixed historical split.

**Phase 2 rolling robustness** represents the later/current robustness workflow using rolling splits and repeated evaluations across time windows.

## Reproducing the Pipeline

A typical reproduction path is:

1. Review `manifests/DATA_PRIVACY_REVIEW.md` before making any data public.
2. Install Python dependencies from `requirements.txt`.
3. Review configuration in `src/config/`.
4. Run preprocessing scripts to rebuild the hourly master dataset, if raw data is available locally.
5. Run A1-B4 dataset-design scripts.
6. Generate split tables and split datasets.
7. Run model training and prediction scripts.
8. Run evaluation and residual-MAD anomaly-detection scripts.
9. Regenerate reports/figures using scripts under `src/reporting/`.

Exact script order is summarized in `docs/reproducibility_notes.md`.

## Included and Excluded Material

Included here: current scripts, configuration, selected processed datasets, selected outputs, figures, documentation, and export manifests.

Excluded from this GitHub-ready export: raw Home Assistant exports, large model artifacts, `.joblib` files, cache/checkpoint folders, duplicate-review folders, unclassified archives, and local-only migration history. Raw Home Assistant data may contain private household behavior and should be reviewed before any public upload. `.joblib` files are intentionally excluded from GitHub.

## Data and Model Artifact Policy

This public-complete version includes processed and derived datasets to support EC3 presentation, academic reproducibility, and transparent review of the research workflow. The included data covers processed hourly/master tables, final A1-B4 modelling datasets, rolling split datasets, predictions, metrics, anomaly-detection outputs, and figures.

Raw Home Assistant exports are excluded for privacy. They may contain timestamped household/prosumer telemetry that could reveal occupancy, appliance activity, or private energy-use behavior.

Trained `.joblib` model artifacts are excluded because they are large binary model outputs and are better regenerated from the included scripts and processed datasets. Models can be regenerated by running the training scripts under `src/model_training/` after installing the dependencies in `requirements.txt`.

Full raw data and trained artifacts may be available upon reasonable request, subject to privacy approval and any applicable research/data-sharing constraints.

## Model Tuning History

The folder `src/model_training/experimental_tuning_history/` documents the development path used to select and validate the final Random Forest workflow. It preserves the earlier HalvingGridSearchCV, stable-parameter selection, polish GridSearchCV, all-8-dataset evaluation, paper model-selection, and alternative-method experiments as research history rather than as the main current pipeline.
